## I — 方法论骨架 (Interpretation)

传统 AIGC 视觉与视频创作普遍困在“抽卡式盲盒生成 + 手工进剪映/AE/Figma 逐帧抠图排版”的低效循环里，面临三大结构性痛点：**多镜头人物/运镜不一致、音乐卡点与后期剪辑极其耗时、生图模型处理多文字排版与二维码必出乱码**。

**Video as Code 与参数化视觉生产流水线**的核心机制，是将“导演调度、视觉设定、剪辑卡点与平面版式”全面**代码化与参数化**，明确划分“生成模型（负责局部视觉纹理）”与“代码/Agent（负责时序编排、逻辑约束、版面合成与后期渲染）”的边界：

1. **时序与调度前置：音乐节拍先行 + 粗糙白模预演 + 参考视频 MCP 拆镜（`@MANISH1027512`、`@TanLuAI`、`@joshesye`）**
   - **音乐先行反常规排轴（`@MANISH1027512`）**：打破“先生画面再找音乐硬凑”的惯例，先让 Agent 分析 BGM 的节拍点（Beat/Drop）与高潮位置，将音乐裁切至目标时长（如 1 分钟内），按节拍先在时间轴上锁死每个镜头的起止位置、时长与台词，最后才按槽位调用生成接口（如 Sumi MCP）产出画面，或盘活存量历史图集（95 秒成片仅耗 1,188 积分，不到全用 Seedance 2.5 直出 1080p 成本的三分之一）。
   - **粗糙白模预演与拉长裁剪省积分（`@TanLuAI`）**：针对复杂动作与多镜头运镜，先用极简几何白模/红白双模（立方体、无脸人）预演摄影机运动、构图与人物走位；**白模越粗糙、越不像真人越好**，因为多余的五官与服装细节会污染后续转绘。预演时故意将时长拉长（如 16 秒目标成片先按 20 秒建模预演，确保立方体把动作做完整），生成后再调速裁剪回目标时长；长片则采用“30 秒环境主片 + 白模补齐高难开头/结尾镜头”的三段式拼接。
   - **参考视频 + MCP 一条龙换人换景（`@joshesye`）**：无需手写分镜脚本，用明确的时间码（如 `00:11 至 00:39`）截取爆款参考视频，交给编码 Agent 挂载剪辑/生成 MCP（如 Renoise MCP），下达结构化替换指令：“保留产品和镜头节奏，只换人物和背景成发布会现场”，由 Agent 自动完成拆镜、重绘、对齐剪辑、配乐与字幕封装；品牌 MG 动效则通过传入品牌 VI 视觉图、Logo、图标与账号定位四要素（或静态网页图+产品图）直接合成动态演示。
2. **多镜头一致性与商业短片参数化：三段式骨架 + 三图职责分工（`@Adam38363368936`、`@TanLuAI`、`@MANISH1027512`）**
   - **商业短片三段式提示词（`@Adam38363368936`）**：固定按 **【参数】**（画幅、时长、全能参考模式）$\rightarrow$ **【唯一核心记忆点】**（全片唯一一句必须出现的关键高光动作，如“轻轻下移墨镜第一次露出眼神直视观众”，绝不贪多以免模型平均分配注意力）$\rightarrow$ **【分段镜头清单】**（按 `0-3s`、`3-6s` 锁定机位与动作）组织。
   - **多镜头三图分工锁一致性（`@Adam38363368936`、`@TanLuAI`）**：先生成人物三视图与关键道具/宠物三视图锁死外观，再生成一张定调首帧图，三张图同时上传图生视频；在提示词开头必须用硬约束声明每张图的唯一职责（如“图 1 管场景与光线，图 2 只管人脸，图 3 只管小狗；只参考面容，不参考服装发型背景；实际视频必须是连续剧情画面，不出现角色卡排版”）。
   - **去 AI 味的“真实不完美感”（`@Adam38363368936`、`@TanLuAI`）**：摒弃过度精致的塑料摆拍，在提示词中注入物理瑕疵与真实机位限制——后视镜构图（带镜面灰尘、反光与画框切割）、闪光灯直闪、轻微手抖、视频压缩感、自然曝光波动与抓拍狼狈感。
3. **代码渲染后期与平面设计（Video & Design as Code）：Remotion/HyperFrames + Design Token + HTML/CSS 海报（`@MANISH1027512`、`@op7418`、`@jinchenma_ai`）**
   - **代码剪辑替代 GUI 时间线（`@MANISH1027512`）**：严格区分“模型做视频（导演与剪辑层）”与“模型生成视频（素材层）”——定格抠像、节拍卡点（如精确到第 13 秒 drop beat 触发特效）、转场与调色全部由 Agent 编写 Remotion / HyperFrames 代码渲染完成，彻底告别手工拖拽剪映或 AE。
   - **风格词库与 Design Token 插件化（`@MANISH1027512`、`@op7418`）**：将难以言传的视觉风格前置为结构化词库（如 13 大领域、157 谱系、1,617 种风格的 VSC 词库与运镜库），并将 PPT、社媒卡片、网页排版的色彩/字体/间距固化为统一 **Design Token** 打包进单一 Agent 插件（如 `dsh-guizang-design`），内置历史作品库支持“一键做同款”。
   - **四段式提示词 + 代码后处理 / HTML 截图出海报（`@op7418`、`@jinchenma_ai`、`@Adam38363368936`）**：
     - 视觉转换提示词固定拆为四段：`输入源（真实照片） → 风格规格（如粗黑描边 2D 等轴测矢量） → 可选信息位（名称、产地风味元素） → 代码后处理（用脚本将原图与生成图自动拼接成高清对比图）`；
     - 商业产品海报采用可替换槽位模板（`4:5 竖版 + 品牌名 + 产品名 + 整体视觉风格 + 整体构图 + 冷凝水珠/冰晶等材质细节`）；
     - 针对带二维码与密集文字的活动/课程海报，**彻底绕开生图模型写字**，直接让 Agent 编写 HTML/CSS 网页并将二维码作为 `<img>` 素材精准嵌入，在浏览器渲染排好版式后直接截图导出（`@jinchenma_ai`）。

## A1 — 应用示例 (Application Example)

### 示例 1: 音乐节拍先行 + 存量素材盘活 + 代码渲染卡点成片
- **类型与来源**: 真实案例 — `@MANISH1027512` 制作《南天门 Club》86 版、95 秒冥府题材成片与“定格抠像卡点”实验（`2026-10-29`、`2026-11-02`、`2026-11-03`、`2026-11-04`）
- **问题/输入**: 创作者手头有一批几个月前用 Midjourney 生成的存量静态图与一段背景音乐，需要制作高燃卡点短片与 95 秒叙事成片；若直接用 Seedance 2.5 全量直出 1080p 视频将消耗约 8,700 积分，且手工在剪映里做第 13 秒 drop beat 定格抠像与调色极其繁琐。
- **方法论的使用**:
  1. 先把 BGM 交给 Agent 分析音频波形，找出节拍点与高潮位置，将音乐剪辑到 1 分钟以内，并按节拍预先排好每个镜头的序号、时长与台词；
  2. 将存量 MJ 静态图整包喂给 Agent 定主题、写分镜与旁白，通过 VSC Plugin 调取准确运镜词，再按排好的时间轴槽位调用 Sumi MCP 生成动态片段；
  3. 后期环节不打开剪映，直接让 Agent 编写 Remotion / HyperFrames 代码，精确在“13 秒 drop beat 落下”的时间戳执行人物定格抠像、转场与统一调色。
- **结论**: “先由音乐节拍锁定时间轴、再按槽位生画面、最后用代码渲染卡点特效”，能同时解决节奏脱节与高昂算力成本两大难题。
- **结果**: 95 秒完整成片仅消耗 1,188 积分（比全量 SD 2.5 1080p 直出节省超 85% 成本），定格抠像与节拍严丝合缝，且整套代码模板可直接复用于后续视频。

### 示例 2: 粗糙白模预演 + 三图分工 + 单一记忆点直出商业级多镜头短片
- **类型与来源**: 真实案例 — `@TanLuAI` 的 16 秒 9 分镜白模直出与 38 秒长片拼接（`2026-10-17`、`2026-10-21`、`2026-11-03`）结合 `@Adam38363368936` 的 Seedance 2.5 墨镜广告与海边公交站 30 秒 9 镜头短片（`2026-10-26`、`2026-11-04`）
- **问题/输入**: 需要交付一条 15–30 秒、包含 4–9 个连续切换镜头的商业品牌广告或动作短剧，要求人物与宠物跨镜头长相不崩、运镜调度丝滑，且避免一眼假的“AI 塑料摆拍感”。
- **方法论的使用**:
  1. **复杂调度走白模预演（`@TanLuAI`）**：针对 16 秒 9 分镜的高空救援/追逐戏，先让 Agent 生成 20 秒的粗糙无脸立方体白模动画（故意拉长 4 秒确保动作做满），确认运镜与走位无误后再注入转绘提示词（声明白模仅作动作与摄影机轨迹参考）并裁剪回 16 秒；
  2. **多角色锁死三图分工（`@Adam38363368936`）**：先出人物三视图与小狗三视图锁死特征，再出一张海边大雨公交站胶片感首帧图；三图同传 Seedance 2.5，并在提示词首行写明“图 1 管场景，图 2 只管人脸，图 3 只管小狗，不出现角色卡排版”；
  3. **商业广告三段式与去 AI 味**：墨镜广告采用“【参数】16:9 15 秒全能参考 + 【唯一核心记忆点】她轻轻下移墨镜第一次露出眼神直视观众 + 4 镜头清单”，并在生活流镜头中加入后视镜灰尘反光、轻微手抖与曝光波动。
- **结论**: 用无细节白模隔离“运镜动作”与“外观纹理”，用三图职责声明隔离“场景、人脸、道具”，用唯一核心记忆点收敛模型注意力，是多镜头一次直出的三大铁律。
- **结果**: 16 秒 9 分镜动作戏与 30 秒 9 镜头剧情片均实现单次生成直出，人物面容跨镜头高度一致，成片具备真实 DV/胶片商业质感。

### 示例 3: Design Token 插件化、四段式代码拼图与 HTML 截图海报
- **类型与来源**: 真实案例 — `@op7418` 的 `dsh-guizang-design` 与饮品微缩建筑对比图（`2026-10-30`、`2026-11-03`）及 `@jinchenma_ai` 的带二维码活动海报制作法（`2026-10-30`）
- **问题/输入**: 创作者需要高频产出两类平面物料：① 风格高度统一的系列社媒卡片、PPT 与“实拍图转插画对比图”；② 包含大量精准中文排版、课程大纲与可扫描二维码的宣传海报（直接用生图模型生成会导致汉字乱码且二维码无法识别）。
- **方法论的使用**:
  1. 将品牌色板、字体层级、圆角与间距固化为一套 Design Token，封装进统一的设计插件，跨 PPT、网页与社媒卡片共享；
  2. 制作饮品微缩插画时，按四段结构下达指令：上传真实饮品照（输入源）$\rightarrow$ 指定粗黑描边 2D 等轴测扁平矢量风（风格规格）$\rightarrow$ 注入咖啡名称与豆子产地风味元素（可选信息位）$\rightarrow$ 要求 Agent 写代码将原图与生成插画自动拼接为高清左右/上下对比图（代码后处理）；
  3. 制作带二维码的多字课程海报时，放弃生图模型直出，直接让 Agent 编写响应式 HTML/CSS 页面，将真实二维码 PNG 作为 `<img>` 节点嵌入版面，在浏览器微调排版后直接全屏/节点截图导出。
- **结论**: 把“图形创意生成”交给生图模型，把“多字排版、二维码嵌入、多图对比拼接與品牌规范约束”交给 HTML/CSS 与代码脚本，才能实现零乱码、100% 可控的商业级平面交付。
- **结果**: 彻底根治海报汉字乱码与二维码失效问题，系列视觉物料实现“一键做同款”的批量标准化产出。

## E — 可执行步骤 (Execution)

**必需输入**:
- **任务目标与交付媒介**：目标产物类型（商业广告短片 / 音乐卡点视频 / 剧情漫剧 / 品牌 MG 动效 / 商业产品海报 / 带二维码多字海报）、画幅比例（如 `16:9`、`9:16`、`4:5`）与目标时长；
- **原始素材资产**：产品/人物参考图、背景音乐（BGM 音频文件）、或明确标定起止时间码的参考视频片段、品牌 VI / Design Token（色值、字体、Logo、二维码原图）。

**交付物与完成标准**:
1. **分轨生产方案与时间轴脚本**：明确每一层由“生成模型”还是“代码渲染（HTML/CSS/Remotion/MCP）”负责，包含精确到秒/节拍的分镜时间轴表；
2. **结构化提示词包与资产绑定清单**：包含三图职责声明（场景/人脸/道具隔离）、唯一核心记忆点、或四段式生图指令；
3. **合成代码与最终视觉产物**：可复用的代码拼接/渲染脚本（或 HTML 海报源码）及无乱码、音画严丝合缝的成片/高清图。

**执行步骤**:

1. **执行“生成 vs 代码”边界分流（模态路由）**
   - 根据视觉任务的精确度要求，将工作流切分为两条互补轨道，严禁让生图/生视频模型硬啃其结构性短板：
     - **凡涉及精确文字排版、二维码/条形码嵌入、UI 界面还原、多图网格拼接、精确到帧的音乐节拍卡点与定格抠像** $\rightarrow$ 划入**代码轨道（Design/Video as Code）**，使用 HTML/CSS 浏览器渲染截图、Python/Canvas 拼图脚本、或 Remotion / HyperFrames / 剪辑 MCP 执行；
     - **凡涉及光影材质表现、人物微表情动作、场景氛围、风格化微缩转换** $\rightarrow$ 划入**生成模型轨道**，并通过结构化参数模板与参考图严密锁死边界。

2. **时序与运镜前置编排（针对视频任务）**
   - **路径 A：音乐驱动型（MV / 卡点宣传片 / 存量图集盘活）**
     1. 先用音频分析脚本或 Agent 解析 BGM，提取 BPM、重拍（Beat）与高潮（Drop）时间戳，将音频裁切至目标时长（如 $\le 60$ 秒）；
     2. 在生成任何画面之前，先输出一张按节拍对齐的《分镜时间轴表》（列明镜头序号、起止秒数、对应节拍事件、画面内容与台词）；
     3. 若有历史存量静态图（如 MJ 图库），优先按故事线匹配进时间轴槽位，再调用图生视频接口补齐动态。
   - **路径 B：复杂动作与运镜驱动型（剧情短片 / 动作戏）**
     1. **粗糙白模预演**：先编写或生成无五官、无服装细节的极简几何白模（立方体/红白双模）动画以验证运镜与走位；
     2. **时长拉长再裁剪**：若目标镜头为 $T$ 秒（如 16 秒），预演建模时拉长至 $1.25T$（如 20 秒）让白模把动作彻底做完，转绘生成后再变速/裁剪回 $T$ 秒；
     3. **长片三段式拼接**：主干环境镜头用高性价比模型生成，开头/结尾的高难度调度镜头用白模转绘补镜，最后拼接成片。
   - **路径 C：爆款复刻型（参考视频换人换景）**
     1. 用精确时间码（如 `00:11–00:39`）圈定参考视频片段；
     2. 通过剪辑/生成 MCP（如 Renoise MCP）或分镜提取工具拆解原片镜头切点，下达“只声明保留什么（产品与镜头节奏）、替换什么（人物与场景背景）”的最小指令，自动重绘并合成字幕配乐。

3. **编写多镜头一致性与商业级参数化提示词**
   - **多镜头三图分工（防串脸与防角色卡分割）**：
     - 准备 3 张参考图：图 1 为环境首帧定调图（锁场景、构图、光线），图 2 为人物三视图（锁面容），图 3 为核心道具/宠物三视图；
     - 在提示词首行强制写入职责隔离声明：
       `图1为视频首帧，画面从图1开始，场景、构图、光线以图1为准；图2仅参考人物面容（不参考服装、发型和背景）；图3仅参考道具/宠物外形。实际视频必须是连续剧情画面，严禁出现角色卡分栏排版、字幕或拟声词。`
   - **商业短片三段式结构**：
     - `【参数】`（画幅比例、总时长、参考模式与总镜头数）
     - `【唯一核心记忆点】`（全片只写**一个**最具张力的关键动作，如“轻轻下移墨镜第一次露出眼神直视观众”）
     - `【分段镜头清单】`（按 `0-3秒`、`3-6秒` 逐段写明机位与动作）。
   - **注入真实感（去 AI 塑料味）**：在生活感或实拍风物料中，显式加入后视镜构图（镜面灰尘、反光、边框遮挡）、闪光灯直闪、轻微手抖、画面压缩感或自然曝光波动。
   - **如果生成的多镜头视频出现注意力分散、动作变形或画面割裂 →** 检查是否塞入了 $\ge 2$ 个核心记忆点或忘记声明“不出现角色卡排版”；立即删减次要动作只留唯一记忆点，并将单次生成拆分为“首帧图定调 + 分镜拼接”。

4. **执行平面视觉四段式生成与 HTML/代码合成交付**
   - **商业产品海报参数化**：套用固定骨架 `[画幅比例 4:5] + [品牌名称] + [产品名称] + 【整体视觉风格】 + 【整体构图】 + [微距材质细节：冷凝水珠/果肉/冰晶/金属反光]`，跨品类复用时仅替换品牌、产品与风格槽位。
   - **四段式转换 + 代码拼图**：执行风格化改造（如实拍图转 2D 等轴测矢量建筑）时，按 `1. 输入源照片 → 2. 风格规格（含描边/视角） → 3. 附加风味信息位（名称/产地元素） → 4. 编写代码脚本将原图与生成图无损拼接为高清对比图` 四步走。
   - **带二维码/多文字海报的 HTML 渲染法**：
     1. 编写基于统一 Design Token（CSS 变量定义主色、辅助色、字体栈与间距）的 HTML/CSS 页面；
     2. 将标题、正文列表与真实二维码图片（`<img src="qrcode.png">`）排入 DOM 容器；
     3. 启动无头浏览器或本地浏览器预览，确认文字零错位、二维码清晰可扫后，按目标分辨率（如 `@2x`/`@3x` DPR）对容器节点截图导出 PNG。
   - **如果代码渲染卡点视频（Remotion/HyperFrames）出现特效触发偏离鼓点 →** 不要靠自然语言让模型盲猜节奏，先用音频脚本导出精确到毫秒的 Beat 时间戳 JSON（如 `drop_beat_ms: 13200`），将该数值作为硬编码常量传入渲染组件。

## B — 适用边界与反例 (Boundaries & Counter-examples)

### 适用前提
- 创作目标追求商业可交付性（品牌一致性、多镜头连贯、精准音乐卡点、无乱码图文排版），而非单纯追求随机艺术涂鸦。
- 执行环境支持运行基础代码脚本（HTML/CSS 渲染、Python/Node 图像处理或 Remotion 等代码视频框架）以承接后处理与版面合成。

### 不适用场景 / 常见误用
- **用精细真人参考图做动作预演（白模反例）**：在预演阶段使用带精致五官和复杂华丽服饰的真人图，会导致后续转绘模型被原图的衣服褶皱与发型死死锁住，无法自由替换新角色造型（`@TanLuAI` 强调：**白模越粗糙、越不像人越好**）。
- **让生图模型直接生成带二维码或大段中文排版的产品海报**：必然导致二维码结构损坏无法扫描、小字粘连乱码；此类需求必须走 HTML/CSS 代码渲染 + 截图路线（`@jinchenma_ai`）。
- **在一条 10–15 秒短片提示词里塞入多个“核心记忆点”**：会导致生成模型平均分配注意力，每个动作都草草带过、毫无商业广告张力（`@Adam38363368936`）。
- **在洁净商业微距特写中滥用“去 AI 味瑕疵”**：后视镜灰尘、手抖、压缩噪点与抓拍狼狈感仅适用于社交生活流与真人 DV 感短片；奢侈品珠宝或高洁净度饮品特写应使用冷凝水珠、冰晶等精致物理材质细节，切勿混用。

### 自检清单
- [ ] 视频生产前是否已先锁定时间轴（通过分析 BGM 节拍排表，或用拉长时长的粗糙白模完成运镜预演）？
- [ ] 多镜头图生视频是否已上传三图（场景首帧 + 人物三视图 + 道具三视图），并在提示词开头明确声明“每张图只管什么”及“禁出现角色卡排版”？
- [ ] 商业短片提示词是否严格遵循“参数 + **唯一**核心记忆点 + 分段镜头清单”三段式？
- [ ] 含二维码、多文字排版或原图对比的平面物料，是否已切换至 HTML/CSS 渲染截图或代码拼接脚本，彻底杜绝生图文字乱码？
- [ ] 跨物料视觉产出是否已提取并复用统一的风格词库与 Design Token？
